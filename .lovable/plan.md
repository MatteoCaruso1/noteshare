
# Fix: Google OAuth 404 Error on Custom Domain

## Problem Summary
When users access the app via the custom domain (`notesharemusic.com`), Google OAuth fails with a 404 error. The OAuth initiation hits `/~oauth/initiate` which is a special Lovable-hosted endpoint that only exists on `*.lovable.app` domains, not on custom domains.

The URL shown: `https://notesharemusic.com/~oauth/initiate?provider=google&redirect_uri=...` returns 404 because this OAuth broker path doesn't exist on the custom domain server.

## Root Cause
The `@lovable.dev/cloud-auth-js` library's `createLovableAuth()` defaults to using `/~oauth/initiate` as a relative path. When the app runs on a custom domain, this relative path resolves to the custom domain instead of the Lovable-hosted OAuth broker.

## Solution
Configure the OAuth broker URL to use the absolute URL from the published Lovable domain (`https://jazz-scene-alive.lovable.app/~oauth/initiate`) instead of a relative path. This ensures the OAuth broker is reached regardless of which domain the user is accessing the app from.

## Implementation

### File: `src/integrations/lovable/index.ts`

Update the `createLovableAuth` call to specify an absolute `oauthBrokerUrl`:

```typescript
// This file is auto-generated by Lovable. Do not modify it.

import { createLovableAuth } from "@lovable.dev/cloud-auth-js";
import { supabase } from "../supabase/client";

// Use absolute URL for OAuth broker to support custom domains
const lovableAuth = createLovableAuth({
  oauthBrokerUrl: "https://jazz-scene-alive.lovable.app/~oauth/initiate",
});

// ... rest of the file remains the same
```

### Important Notes

1. This change requires modifying an auto-generated file. The comment says "Do not modify it" but this is necessary to support the custom domain.

2. After the OAuth flow completes on the Lovable domain, the user will be redirected back to the `redirect_uri` which is correctly set to the custom domain (`https://notesharemusic.com/auth`).

3. The `supportedOAuthOrigins` may also need to include the custom domain if postMessage authentication is used for fallback.

## Technical Details

```text
Current Flow (Broken):
User on notesharemusic.com → clicks "Sign in with Google"
→ Redirects to notesharemusic.com/~oauth/initiate (404!)

Fixed Flow:
User on notesharemusic.com → clicks "Sign in with Google"  
→ Redirects to jazz-scene-alive.lovable.app/~oauth/initiate (OAuth broker)
→ Google OAuth consent screen
→ Redirects back to notesharemusic.com/auth (user's redirect_uri)
→ Session established, user logged in
```
